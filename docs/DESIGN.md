# 확정 설계

변경은 사용자 승인 후에만 한다. 구현 중 필요한 세부 결정은 docs/DECISIONS.md에 기록한다.

## 1. 대상 환경

| 항목 | 값 |

## 2. 기술 스택

| 항목 | 결정 |
|---|---|
| 언어 | Kotlin (네이티브 캡처 DLL만 C++) |
| 구조 | Kotlin Multiplatform: shared / androidApp / desktopApp |
| 안드로이드 SDK | minSdk 26, compileSdk 36, targetSdk 36 |
| 안드로이드 ABI | release: arm64-v8a만 / debug: arm64-v8a + x86_64 (에뮬레이터 테스트용) |
| 앱 화면 UI | Jetpack Compose (안드로이드), Compose Multiplatform (윈도우) |
| 안드로이드 오버레이 | 일반 View + WindowManager (Compose 사용 안 함) |
| 저장 | JSON 파일, kotlinx.serialization. Room 사용 안 함 |
| 이미지 인식 | OpenCV 4.x 최신 안정판 (16KB 페이지 대응 버전), 안드로이드 SDK / Java 패키지 |
| 윈도우 네이티브 호출 | JNA |
| 윈도우 배포 | jpackage 기반 msi, 런타임 포함 |
| 배포 | 개인 설치 전용. 플레이스토어 배포 없음 |

## 3. 핵심 구조

### 3.1 좌표
- 저장: 비율 좌표(0~1) + 등록 당시 해상도, 방향
- 기준: 실제 전체 화면 픽셀 (안드로이드는 WindowMetrics 기준, 컷아웃/바 포함)
- PC: 기본은 "대상 창 클라이언트 영역 기준", 옵션으로 "모니터 기준"

### 3.2 클릭 엔진
- `shared`에 `ClickEngine` 인터페이스 (tap, longPress, swipe, doubleTap, 키 입력은 PC만)
- 안드로이드 구현: AccessibilityService.dispatchGesture
- PC 구현: SendInput
- 향후 옵션: Shizuku 구현 (안드로이드)

### 3.3 타이밍 엔진
- 전용 스레드 (안드로이드 HandlerThread / PC 전용 스레드)
- 기준 시계: 안드로이드 SystemClock.uptimeMillis, PC QueryPerformanceCounter
- 절대시각 스케줄링: 다음 실행 시각 = 시작 시각 + 누적 예정 간격. 이전 실행 지연이 누적되지 않게 한다
- PC: 실행 중 timeBeginPeriod(1), 정지 시 timeEndPeriod(1)
- 모든 실행을 "예정 시각 / 실제 시각"으로 로그 기록
- 제스처 진행 중 새 제스처 전송 금지. 최소 간격은 3단계 실측 후 DECISIONS.md에 확정

### 3.4 화면 캡처
- 안드로이드: MediaProjection + ImageReader, foregroundServiceType=mediaProjection, 세션 유지
  - 캡처 해상도 = 현재 화면 해상도의 절반 (FHD+ 540x1170, QHD+ 720x1560), RGBA 버퍼 직접 읽기, Bitmap 변환 금지 (디버그 스냅샷 제외)
  - 화면 해상도 설정 변경(S26 울트라)을 감지하면 캡처 재구성, 해당 프로필 템플릿에 "배율 재확인 필요" 표시
  - 동의는 앱 세션당 1회, "전체 화면" 선택 안내
  - 회전 시 VirtualDisplay/ImageReader 재구성
  - 보안 창 등으로 캡처가 전부 검정이면 경고
  - 보조: AccessibilityService.takeScreenshot (1초 1회 제한, 느린 감시 전용)
- PC: DXGI Desktop Duplication (native/win-capture DLL), 실패 시 java.awt.Robot 대체
- 공통: 필요한 ROI만 읽는다

### 3.5 인식
| 방식 | 용도 |
|---|---|
| 단일점 색 | 단순 on/off |
| 다중점 색 (기본) | 기준점 + 주변점 상대좌표/색, 전부 허용오차 이내일 때 일치 |
| 영역 색 찾기 | ROI 안에서 목표 색 위치 탐색 |
| 템플릿 매칭 | OpenCV matchTemplate, ROI, 흑백/컬러 선택, 투명 PNG 마스크, 일치도 기준값(기본 0.85) |
| 배율 자동 탐색 | 등록 시 0.5~1.5배 탐색 → 최적 배율 저장, 이후 해당 배율만 사용 |
| OCR | 선택 단계 (ML Kit) |

### 3.6 규칙 엔진 (입력 → 출력)
- 입력: 단일점 색 / 다중점 색 / 영역 색 / 템플릿 / 각 조건의 "사라짐"
- 출력: 고정 좌표 / 영역 템플릿 탐색 위치 / 영역 색 탐색 위치 / 입력 발견 위치 + 상대 오프셋 / 시퀀스 실행 / 키 입력(PC)
- 옵션: 쿨다운(ms), 우선순위, 사용 여부, 출력 탐색 실패 처리(건너뛰기 / 재시도 n회 / 전체 정지), 여러 개 발견 시(첫 번째 / 최고 일치도 / 전부 순서대로), 이미지 내 누를 지점
- 입력 감시는 빠른 방식으로 상시, 출력 탐색은 발동 시에만
- 규칙 발동 시 실행 중인 시퀀스는 일시 대기 후 재개
- 테스트 모드: 실제 입력 없이 발견 위치와 일치도를 오버레이에 표시

### 3.7 시퀀스
- 단계: 동작 종류(탭/롱프레스/스와이프/더블탭/키), 좌표, 누름 시간, 대기 시간
- 반복: 횟수 / 무한 / 총 실행 시간
- 확장: 랜덤 오프셋(±px, ±ms), 조건 분기(단계 이동), 나타날 때까지 대기(타임아웃)

### 3.8 데이터
```
Profile { name, baseResolution, orientation, sequences[], rules[], images[], settings, keymap? }
ImageAsset { id, name, file, bestScale, threshold, useMask, colorMode, clickPoint }
```
- 앱 내부 저장소 JSON + PNG
- 내보내기/가져오기: zip (profile.json + images/)
- 폰↔PC 가져오기: 구조는 유지, 좌표와 이미지는 "재설정 필요" 표시

### 3.9 기기별 차이 처리
- 모든 로그와 진단 파일에 기기 모델, One UI/Android 버전, 현재 해상도를 기록
- 프로필에 등록 기기 모델과 해상도를 저장. 다른 기기에서 열면 좌표는 비율로 변환하고, 템플릿은 배율 자동 탐색을 1회 다시 수행
- 기기별 실측 최소 간격, 캡처 fps, 매칭 시간은 DECISIONS.md에 기기별로 기록하고 앱 기본값은 가장 느린 기기(S24 FE) 기준

## 4. 안드로이드 UI

### 4.1 플로팅 버블과 툴바
- 버블: 드래그 이동, 화면 가장자리 붙기, 상태 표시(대기/실행/일시정지)
- 펼친 툴바(기본 가로, 설정에서 세로): 시작/일시정지(토글) · 추가(+) · 제거(-) · 정지 · 더보기(⋯)
- 더보기: 규칙, 시퀀스 목록, 마커 숨기기, 프로필, 설정, 툴바 접기
- 툴바 아래 진행 표시: "현재/전체 · 반복 n회째"

### 4.2 동작 규칙
- 시작/일시정지: 일시정지 후 재시작은 멈춘 단계부터
- 정지: 완전 정지, 다음 시작은 1번부터
- 추가(+): 화면 중앙에 (마지막 번호 + 1) 마커 생성, 드래그로 위치 지정
- 제거(-): 제거 모드 진입(마커 빨강), 마커 탭 시 삭제 후 뒷번호 자동 당김, 다시 - 누르면 종료, 마지막 삭제 1회 되돌리기(3초 안내)
- 실행 중 +/-: 동작하지 않고 "일시정지 후 편집하세요" 안내
- 마커: 번호 표시, 번호 순서대로 점선 연결, 실행 중 현재 마커 강조, 실행 중 터치 불가 + 반투명
- 마커 길게 누르기: 상세 창(번호 변경 시 나머지 자동 정렬, 대기/누름 시간)
- 마커 크기, 투명도 설정

### 4.3 안전
- 긴급 정지: 볼륨 아래 키(접근성 키 필터), 알림의 정지 버튼
- 볼륨 키 할당은 설정에서 변경 가능 (볼륨 위 = 시작/일시정지 기본)
- 실행 중 화면 꺼짐 방지
- 종료 조건: 반복 횟수, 총 시간, 특정 조건 감지

### 4.4 온보딩
- 오버레이 권한, 접근성, 제한된 설정 해제 안내(앱 정보 → ⋮ → 제한된 설정 허용), 삼성 절전 예외(설정 → 배터리 → 백그라운드 사용 제한), 알림 권한
- 각 항목 상태를 실시간 표시

## 5. PC UI와 키맵

### 5.1 창/오버레이
- 항상 위 + 투명 + 클릭 통과 오버레이, 툴바 구성은 안드로이드와 동일
- 트레이 아이콘 메뉴(시작/정지/종료)
- DPI: Per-Monitor V2
- 실행 모니터 1개 선택, 대상 창 선택, 대상 창이 전면이 아니면 자동 일시정지
- 설정: 관리자 권한으로 실행 옵션

### 5.2 키맵
- 감지: WH_KEYBOARD_LL, WH_MOUSE_LL 저수준 훅
- 조합: 키 1개 또는 2개, 누르는 순서 무관
- 사용 가능: 일반 키, F1~F24, 숫자패드, 좌/우 Ctrl·Shift·Alt 구분, 마우스 옆 버튼 2개
- 등록 불가: Win 키, Ctrl+Alt+Del, Alt+Tab, Alt+F4 등 시스템 키
- 키맵별 "게임에 전달 / 차단" (기본 차단)
- 적용 범위: 공통 키맵 + 프로필 키맵(우선)
- 충돌 검사(저장 시): 동일 조합 중복, 단독 키와 그 키를 포함한 조합의 공존
- 설정 화면: 칸 선택 → 입력 대기 → 최대 2키 기록 → 전부 떼면 확정, Esc 취소, Backspace 비우기 (Esc/Backspace는 단독 할당 불가, 조합 일부로는 가능), 기본값 복원
- 동작은 목록에서 선택하는 구조 (확장 시 항목 추가만)

## 6. 알려진 제약
- dispatchGesture 지연과 스케줄링 오차로 1ms 정밀도는 보장되지 않는다. 실측값을 DECISIONS.md에 기록한다
- MediaProjection 동의는 세션마다 필요하다
- 캡처 주기 한계로 색 반응 지연이 수십 ms 존재한다
- 관리자 권한 게임에는 매크로도 관리자 권한 필요
- 독점 전체화면 게임은 캡처 실패 가능 → 테두리 없는 창 모드 권장
