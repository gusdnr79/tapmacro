1이 프로젝트는 뭔가요

휴대폰과 윈도우 PC에서 원하는 곳을 자동으로 반복해서 눌러주는 앱을 만듭니다. 순서대로 누르기, 특정 색이나 아이콘이 나타나면 누르기 같은 기능이 들어갑니다.

만드는 과정은 0단계부터 10단계까지 나뉘어 있고, 각 단계는 Claude Code 안에서 AI 세 명이 나눠서 진행합니다.

🧪 테스트 담당이
확인 방법을 먼저 정함→ 🛠️ 개발 담당이
만듦→ 🧪 테스트 담당이
실제로 돌려봄→ 🔍 검수 담당이
합격/불합격 판정→ 🙋 사람이
눈으로 확인

불합격이면 AI들이 알아서 고치고 다시 확인합니다. 우리가 할 일은 시작 명령을 넣고, 질문에 답하고, 폰으로 확인하는 것입니다.

5GitHub로 같이 일하는 방식

모든 작업 결과는 GitHub(클라우드)에 모입니다. 각자 PC는 작업대일 뿐이고, 진짜 원본은 GitHub에 있습니다. 그래서 컴퓨터가 고장 나도 올려둔 작업은 사라지지 않고, 다른 사람이 이어서 할 수 있습니다.

규칙 5가지

  1. main은 잠겨 있습니다누구도 main에 직접 올릴 수 없습니다. 관리자가 PR을 승인해야만 합쳐집니다.
  2. 단계마다 갈래 하나2단계 작업은 전부 stage-2 갈래에서 합니다. Claude가 자동으로 만들고 전환합니다.
  3. 시작 전엔 받고, 끝나면 올린다작업 전에 /sync, 중간중간 Claude가 "올려둘까요?" 물으면 "네".
  4. 한 갈래에 한 사람씩같은 단계를 두 사람이 동시에 돌리지 않습니다. 넘길 때는 올려두고 팀 채팅에 알립니다.
  5. 요청은 Issue로"이렇게 바꾸면 좋겠다"는 /request로 게시판에 올립니다.

GitHub 웹사이트에서 볼 것

탭무엇을 보나해도 되는 것
Code현재 본선 파일들. docs/STATUS.md를 누르면 진행 상황이 표로 보입니다.보기만
Issues아이디어·버그·질문 게시판읽기, 댓글 달기
Pull requests합치기 요청서. 단계 결과 요약이 들어 있습니다.읽기, 댓글 달기 (병합 버튼은 관리자만)
GitHub 웹에서 파일 수정 금지웹사이트에서도 연필 아이콘으로 파일을 고칠 수 있지만, 절대 누르지 마세요. 모든 변경은 Claude의 단계 절차로만 합니다.

6처음 한 번만 하는 준비

윈도우 PC 기준입니다맥을 쓰면 관리자에게 먼저 말해주세요. 회사 컴퓨터는 회사 규정 문제가 생길 수 있으니 개인 PC를 권장합니다.

A. 계정

  1. GitHub 가입github.com에서 가입하고 아이디를 관리자에게 알려주세요.
  2. 초대 수락관리자가 초대하면 이메일이 옵니다. "Accept invitation"을 누르세요.
  3. Claude 유료 요금제각자 Claude 계정의 유료 요금제(Pro 이상)가 필요합니다. 계정 공유 금지.

B. 프로그램 설치 (이 순서대로)

  1. Git for Windowsgit-scm.com에서 설치. 설치 중 "기본 편집기" 선택 화면이 나오면 Visual Studio Code를 고르고, 나머지는 기본값으로 "Next".
  2. VS Codecode.visualstudio.com에서 설치. 설치 옵션에서 "PATH에 추가"와 "Code(으)로 열기" 항목을 체크하세요.
  3. GitHub CLIcli.github.com에서 설치. Claude가 PR과 Issue를 만들 때 씁니다.
  4. Android Studiodeveloper.android.com/studio에서 설치 후 한 번 실행해서 기본 구성요소 설치까지 끝내세요. 앱 빌드와 폰 연결 도구(adb)가 들어 있습니다. (확인 담당만 하는 사람은 생략 가능)

설치가 끝나면 PC를 한 번 재시작하세요.

C. VS Code 기본 설정

  1. 한국어로 바꾸기 (선택)VS Code 왼쪽의 네모 4개 아이콘(확장, Ctrl+Shift+X) → "Korean Language Pack" 검색 → 설치 → 재시작
  2. Claude Code 확장 설치확장 화면에서 "Claude Code" 검색 → 제작자가 Anthropic인지 확인 → 설치
  3. GitHub 로그인왼쪽 아래 사람 모양 아이콘(계정) → "GitHub로 로그인" → 브라우저에서 승인
  4. 터미널 열어보기메뉴 보기 → 터미널, 또는 Ctrl+` (숫자 1 왼쪽 키). 아래쪽에 PowerShell 창이 열립니다. 앞으로 "터미널에 입력"은 모두 여기입니다.

D. 터미널에서 한 번만 입력

VS Code 터미널에 한 줄씩 붙여넣고 Enter. 이름과 이메일은 본인 것으로 바꾸세요.

git config --global user.name "내GitHub아이디"
git config --global user.email "내이메일@example.com"
git config --global core.longpaths true
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
gh auth login
  • Set-ExecutionPolicy에서 확인을 물으면 Y
  • gh auth login은 GitHub.com → HTTPS → 브라우저로 로그인 순서로 고르면 됩니다

그다음 Claude Code 명령줄 버전도 설치합니다. Claude Code 공식 설치 문서(code.claude.com/docs)의 Windows용 설치 명령을 복사해서 같은 터미널에 붙여넣으세요. 설치 후 터미널을 닫았다 열고 아래로 확인합니다.

claude --version
왜 두 번 설치하나요?VS Code 확장은 보기 편한 대화창이고, 명령줄 버전은 확장에서 안 되는 기능이 있을 때 쓰는 예비용입니다. 둘은 같은 대화 기록을 공유합니다.

E. 저장소 받기

문서·바탕화면 폴더에 받지 마세요윈도우의 문서·바탕화면 폴더는 OneDrive와 동기화되는 경우가 많아서 파일이 꼬입니다. 반드시 C:\dev에 받으세요.
  1. 폴더 만들기터미널에 입력: 
    mkdir C:\dev
  2. 클론VS Code에서 Ctrl+Shift+P → "Git: 복제(Clone)" 입력 → "GitHub에서 복제" → 저장소 선택 → 저장 위치로 C:\dev 선택
  3. 열기"복제한 저장소를 여시겠습니까?"가 뜨면 열기
  4. 신뢰"이 폴더의 작성자를 신뢰하시겠습니까?"가 뜨면 예, 작성자를 신뢰합니다. 신뢰하지 않으면 Claude Code 확장이 동작하지 않습니다.
  5. 권장 확장 설치오른쪽 아래에 "이 저장소에 권장되는 확장이 있습니다"가 뜨면 모두 설치

F. Claude Code 연결

  1. Claude 창 열기왼쪽 파일 목록에서 아무 파일(예: CLAUDE.md)을 하나 열면, 편집기 오른쪽 위에 ✨ 불꽃 모양(Spark) 아이콘이 보입니다. 누르세요.
  2. 로그인처음이면 "Sign in"을 누르고 브라우저에서 Claude 계정으로 승인
  3. 프로젝트 신뢰Claude가 이 폴더를 신뢰할지 물으면 신뢰. 이래야 안전장치가 켜집니다.
  4. 명령 확인입력창에 /를 쳐서 stage, sync, status, request가 목록에 보이는지 확인
목록에 명령이 안 보이면확장 창은 일부 명령만 지원할 수 있습니다. 그럴 땐 VS Code 터미널에서 claude를 입력해 명령줄 버전으로 쓰세요. 같은 명령이 그대로 됩니다. 터미널에서 실행해도 VS Code와 자동으로 연결됩니다.

G. 폰 보유자만: 폰 연결

  1. 개발자 옵션 켜기설정 → 휴대전화 정보 → 소프트웨어 정보 → "빌드번호" 7번 연속 탭
  2. USB 디버깅 켜기설정 → 개발자 옵션 → USB 디버깅
  3. 연결 허용데이터 전송이 되는 USB 케이블로 PC에 연결 → 폰에 뜨는 "USB 디버깅 허용"에서 "이 컴퓨터에서 항상 허용" 체크 후 허용
  4. 확인VS Code 터미널에서 adb devices → 기기가 device로 보이면 완료
S26 울트라 보유자화면 해상도 설정 위치를 알아두세요: 설정 → 디스플레이 → 화면 해상도. 테스트 중 "FHD+로 바꿔주세요", "QHD+로 바꿔주세요" 요청이 옵니다.
준비 끝 확인Claude 창에서 /status를 입력했을 때 프로젝트 상황이 나오면 완료입니다.

8매번 하는 작업 순서

  1. VS Code 실행최근 항목에서 C:\dev\저장소이름이 열립니다. 안 열리면 파일 → 폴더 열기.
  2. Claude 창 열기✨ 아이콘 또는 Ctrl+Esc
  3. /sync다른 사람이 올린 최신 작업을 받습니다. 항상 제일 먼저.
  4. /status지금 상황과 내 차례인지 알려줍니다.
  5. 내 차례면 안내된 명령 실행대부분 /stage 숫자. 아니면 앱 확인이나 아이디어 등록을 해도 좋습니다.
  6. 팀 채팅에 알리기시작할 때 "2단계 시작합니다", 끝나거나 넘길 때 Claude가 준 요약을 붙여넣기.
한 단계에 한 사람만같은 단계를 두 사람이 동시에 돌리면 작업이 꼬입니다. 반드시 채팅으로 먼저 알리세요.

/request S26 울트라에서 마커가 너무 작아 보여

Claude가 내용을 정리해서 보여주고, 확인하면 GitHub Issues에 올립니다. 버그라면 어떤 폰 · 무엇을 했는지 · 기대한 것 · 실제 결과 · 스크린샷을 물어봅니다. 관리자가 보고 어느 단계에 넣을지 정합니다.

왜 바로 고치면 안 되나요?여러 명이 각자 고치면 설계가 뒤엉키고, 테스트와 검수를 안 거친 코드가 섞입니다. 모든 변경은 요청 → 관리자 결정 → 단계 진행으로만 들어갑니다.

13절대 하지 말 것

  • Claude에게 /stage 없이 "코드 고쳐줘", "기능 추가해줘" → /request로
  • 관리자가 정하지 않은 단계 시작, 남이 진행 중인 단계 동시 실행
  • VS Code 소스 제어 창의 커밋·동기화·브랜치 전환 버튼 누르기
  • GitHub 웹에서 파일 수정, PR 병합(Merge) 버튼 누르기
  • VS Code 탐색기나 윈도우 탐색기에서 프로젝트 파일 지우기·옮기기·직접 고치기
  • 저장소를 OneDrive·문서·바탕화면 폴더에 두기
  • Bypass·Edit automatically 모드 사용, 위험 명령 허용 (10장)
  • Claude·GitHub 계정, 비밀번호, 토큰 공유
  • 저장소 주소나 파일을 팀 밖으로 공유 (비공개 저장소)
  • 회사 컴퓨터에 폰 연결, 회사 컴퓨터에서 PC용 매크로 테스트

14문제가 생겼을 때

먼저 Claude에게 "방금 뭐가 잘못된 거야? 쉽게 설명해줘"라고 물어보세요. 해결이 안 되면 화면 전체를 캡처(Win+Shift+S)해서 관리자에게 보내세요.

"충돌(conflict)"이라는 말이 나왔어요

다른 사람 작업과 겹친 상태입니다. 아무것도 더 하지 말고 관리자에게 연락하세요. Claude도 이 경우 자동으로 멈춥니다.

"저장 안 된 변경이 있습니다"라며 멈췄어요

이전 작업이 기록되지 않고 남아 있습니다. 지우지 말고 관리자에게 알려주세요. 본인이 하던 단계라면 /stage N을 다시 실행해보세요.

✨ Claude 아이콘이 안 보여요
  • 파일을 하나 열어야 편집기 오른쪽 위에 나타납니다
  • 폴더를 "신뢰"하지 않으면(제한 모드) 확장이 동작하지 않습니다. 왼쪽 아래나 위쪽의 "제한 모드" 표시를 눌러 신뢰로 바꾸세요
  • Ctrl+Shift+P → "Developer: Reload Window"
/stage 같은 명령이 목록에 없어요

VS Code 터미널에서 claude를 입력해 명령줄 버전으로 실행하세요. claude를 못 찾는다고 나오면 6장 D의 명령줄 버전 설치를 다시 확인하고 터미널을 새로 여세요.

adb devices에 폰이 안 보여요
  • 충전 전용 케이블이 아닌지 확인
  • 폰 잠금을 풀고 다시 연결, 폰의 USB 디버깅 허용 팝업 확인
  • 폰 알림창에서 USB 모드를 "파일 전송"으로
  • 폰을 여러 대 연결했다면 전부 목록에 나오는지 확인. 하나만 나오면 케이블이나 포트를 바꿔보세요
  • adb를 못 찾는다고 나오면 Android Studio 설치가 덜 된 것. 관리자에게 문의
"빌드 실패"라고 나와요

AI가 한 번 더 시도합니다. 두 번 실패하면 멈추고 알려주니, 그 메시지를 캡처해서 관리자에게 보내세요.

파일 경로가 너무 길다는 오류가 나요

6장 D의 git config --global core.longpaths true를 했는지, 저장소가 C:\dev 아래에 있는지 확인하세요.

Claude가 오래 반응이 없어요

아래쪽 "n agents"를 눌러 AI들이 일하고 있는지 보세요. 30분 넘게 변화가 없으면 Esc로 멈추고 /stage N으로 다시 이어가세요.

사용량 한도에 도달했대요

안내된 시간 이후 /stage N으로 이어가면 됩니다. 급하면 "지금까지 작업 GitHub에 올려줘"라고 한 뒤 팀 채팅에 올려 다른 사람이 이어받게 하세요. 입력창에 /usage를 치면 남은 사용량을 볼 수 있습니다.

안전장치(guard-paths) 오류가 나요

6장 D의 Set-ExecutionPolicy를 했는지 확인하세요. 했는데도 나오면 관리자에게.

실수로 뭔가 허용해버렸어요

Esc로 멈춘 뒤 "방금 무슨 일을 했는지 쉽게 설명해줘"라고 물어보고, 그 답을 캡처해서 관리자에게 보내세요. 기록이 GitHub에 남아 있어서 대부분 되돌릴 수 있습니다.
