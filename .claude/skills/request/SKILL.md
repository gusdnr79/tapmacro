argument-hint: "<하고 싶은 말>"

---

사용자 입력: $ARGUMENTS

사용자는 비개발자일 수 있다. 코드나 설계 문서는 수정하지 않는다.

1. 입력이 비어 있으면 무엇을 요청하고 싶은지 물어본다.
2. 종류를 정한다: 아이디어 / 버그 / 질문. 애매하면 물어본다.
3. 버그면 필요한 정보가 빠졌을 때 한 번에 묻는다: 몇 단계 앱인지, 무엇을 했는지, 기대한 것, 실제 결과, 스크린샷 유무.
4. 아래 형식으로 제목과 본문을 정리해서 사용자에게 보여주고 등록해도 되는지 확인받는다.
   - 제목: `[아이디어|버그|질문] 한 줄 요약`
   - 본문: 작성자(`git config user.name`), 날짜, 내용, (버그면) 재현 방법/기대/실제, 관련 단계(STAGES.md에서 찾아 추정하고 "추정"이라고 표시)
   - 아이디어면 DESIGN.md와 충돌하거나 이미 계획된 내용인지 확인해서 본문 끝에 "참고: 이미 N단계에 계획됨" 같은 메모를 붙인다
5. 승인되면 `gh issue create --title ... --body ... --label <아이디어|버그|질문>` 으로 등록한다. 라벨이 없어서 실패하면 라벨 없이 다시 등록한다.
6. `gh`를 쓸 수 없으면 제목과 본문을 복사하기 좋게 보여주고 GitHub 저장소의 Issues 탭에 붙여넣으라고 안내한다.
7. 등록된 주소를 알려주고 "관리자가 검토합니다"라고 마무리한다.
